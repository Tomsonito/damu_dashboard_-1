# Дашборд Даму

Внутренний аналитический дашборд на Dash/Plotly. Показывает показатели МСП
по регионам Казахстана. Не публикуется в интернет, работает во внутренней сети.

## Читать в первую очередь

- **[ROADMAP.md](ROADMAP.md)** — план по этапам, что сделано и что впереди
- **[план по этапам визуализации/CODE_GUIDE.md](план%20по%20этапам%20визуализации/CODE_GUIDE.md)** —
  разбор кода: какой файл за что отвечает, что делает каждая функция, что где менять

## Где сейчас проект

Этап 0 закрыт. **Этап 1** закрыт по коду, ждёт согласования с заказчиком:
дашборд работает на реальных данных из PostgreSQL — карточки-показатели
(включая производную «Согласно плану %»), 17 видов диаграмм, таблица, фильтры.
**Этап 2** закрыт: `python -m etl.run` инкрементально ведёт хранилище
`data/analytics.duckdb` со сверкой и логом прогонов.
**Этап 3** закрыт: сайт читает DuckDB через кэш (ключ — версия данных),
открытая страница раз в 30 сек сверяет версию и перерисовывается сама,
не сбрасывая фильтры. **Этапы 4–5 не начаты.**

## Ключевые решения — их важно не сломать

**Данные едут из боевой БД; Excel был временной затычкой и своё отслужил.**
Цепочка: PostgreSQL → `etl/run.py` (проверка отпечатка источника → пересчёт →
сверка → версия) → `data/analytics.duckdb` (таблицы `facts` и `versions`) →
сайт. CSV в этой цепочке больше нет.

**Смена источника стоит одной функции.** Всё, что знает про формат хранения —
`load_facts()` в `core/data.py`. Страницы, диаграммы и реестр показателей
о формате не знают ничего. Оба переезда — Excel → БД и CSV → DuckDB — меняли
только её тело. Если источник сменится снова, форму таблицы фактов сохранить.

**Архитектура «узкая талия».** Каждый источник — файл или таблицы БД —
разбирается своим маленьким разборщиком в **одну общую таблицу фактов**.
Виджеты читают только её. Новый источник = новый разборщик + строки
в `config.yaml`, правок в `pages/` не требуется.

**Оригиналы в `data/raw/` не изменяются никогда.** Вся правка — в коде разбора,
чтобы результат был воспроизводим и было с чем сверяться.

**`core/data.py` — единственная дверь к данным.** Страницы не читают файлы сами.

**Добавить вид диаграммы = одна функция с `@chart` в `core/charts.py`.**
Реестр на декораторе, список в интерфейсе строится автоматически.

**Показатели описываются в `config.yaml`**, а не в коде: название, единица,
масштаб показа. Переименование и смена масштаба — правка YAML без кода.

## Соглашения

- **Код — английский** (имена переменных, функций, колонок). **Текст интерфейса — русский.**
- Скрипты из `etl/` запускать из корня как модуль: `python -m etl.parse_msp`,
  иначе не найдутся импорты из `core/`.
- Dash 4: метода `run_server` больше нет, только `app.run()`. Учебники в интернете
  написаны под Dash 2 и вводят в заблуждение.
- Числа: разряды неразрывным пробелом, символ тенге `₸`. Кириллицу в заглушках
  держать намеренно — ранняя проверка шрифтов.
- Кракозябры при `print()` русского текста в терминале Windows — это кодировка
  консоли, не ошибка кода. В браузере всё нормально.

## Запуск

```bash
python -m etl.run         # БД -> data/analytics.duckdb; пропустит, если источник не менялся
python app.py             # поднять сайт на 127.0.0.1:8050
```

CSV-файлы в `data/` сайту больше не нужны: он читает таблицу `facts`
из DuckDB. `etl/load_budget.py` остался как разборщик, его дёргает `etl/run.py`.

Горячая перезагрузка отключена намеренно (`dev_tools_hot_reload=False`) — она
сбрасывала выбранные фильтры при каждой правке файла. После изменений в коде
страницу обновлять вручную, F5.

## Как работать с этим пользователем

Объяснять **по шагам и простым языком**, с разбором «почему именно так»,
а не только «что сделать». Проверять код запуском до того, как показывать
результат. Не выдумывать свойства библиотек — сверяться с установленной версией.
