# cron: прогон ETL каждые 5 минут. Инкрементальность внутри etl.run
# делает холостой прогон дешёвым (~0.1 сек), поэтому частый запуск не грузит
# ни сервер, ни боевую БД: пересчёт идёт только когда источник изменился.
#
# Заодно каждый прогон дёргает шлюз публикации 9:00 — поэтому даже если
# все браузеры закрыты, дозревшие версии и правки плана опубликуются: их
# подхватит первый же прогон после срока (решение 23.07.2026).
#
# Установка (этап 5, на сервере, из-под служебного пользователя, НЕ root):
#   crontab -e
#   # вставить строку ниже, подставив <путь-к-проекту>
#   crontab -l          # проверить, что задание на месте
#
# !! Часовой пояс: 9:00 публикации считается по часам сервера. Убедиться,
# что сервер стоит на казахстанском времени (timedatectl). В UTC публикация
# молча съедет на 14:00 по Астане.

# ┌ минута (*/5 — каждые 5)
# │      ┌ час     ┌ день  ┌ месяц  ┌ день недели
# │      │         │       │        │
*/5 * * * * cd <путь-к-проекту>/damu_dashboard && .venv/bin/python -m etl.run >> data/cron.log 2>&1

# Пояснения:
#   cd ... && ...  — etl.run запускается из корня проекта как модуль
#                    (python -m etl.run), иначе не найдутся импорты из core/.
#   >> data/cron.log 2>&1 — вывод и ошибки в файл: cron сам ничего не
#                    показывает, лог — единственный свидетель. Внутренний
#                    лог прогонов ETL пишется отдельно в data/etl.log.
