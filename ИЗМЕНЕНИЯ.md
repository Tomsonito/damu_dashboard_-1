# Изменения — сессия после компакта

## 1. Производительность: объединённый опрос DuckDB

**Проблема.** Коллбэк `poll_version` (каждые 30 сек с каждого открытого браузера)
делал три отдельных открытия DuckDB: `get_published_version()` + `_plan_stamp()`
+ `_last_publish_time()`. Каждое — ~25–34 мс, потому что при закрытии соединения
DuckDB выгружает базу и следующее открытие грузит её заново. Итого ~81 мс
вместо ~25.

**Решение.** Функция `poll_health()` в `core/data.py` — одно соединение,
три запроса подряд, одно закрытие. Возвращает словарь со всеми данными
опроса разом.

**Файлы:**

- `core/data.py` — добавлена `poll_health()`, `_display_version()`,
  `_last_update_from_health()`. `get_display_version()` и
  `get_last_update_parts()` переделаны под обёртки над `poll_health()`.
- `app.py` — `poll_version()` вызывает `poll_health()` один раз и
  передаёт словарь в хелперы, вместо трёх отдельных вызовов.

**Измерение.** Вручную не замерено (сайт не запускался без разрешения).
Логика замера: `time.perf_counter()` вокруг `con.execute()` — в тесте
на `test_version_and_plan` видно, что одно соединение vs три отдельных.

## 2. Первый тик опроса — через 10 сек, не сразу

**Проблема.** `dcc.Interval` с `interval=30000` стрелял в 0:00 после
открытия страницы. Пользователь ещё не успел посмотреть экран, а запрос
уже ушёл в базу.

**Решение.** Interval стартует с `interval=10_000`. На первом тике
коллбэк возвращает `interval=30_000` обратно в `Output("data-poll", "interval")`,
и следующие опросы идут раз в 30 сек.

**Файл:** `app.py` — `poll_version()` принимает `State("data-poll", "interval")`,
сравнивает с `10_000` и возвращает `next_interval` пятым выходом.
`serve_layout()` — `dcc.Interval(id="data-poll", interval=10 * 1000)`.

## 3. Mockup → нули

**Проблема.** На главной экране стояли числа из эскиза (620, 540, 1860…)
— пользователь попросил заменить на нули, пока не готов источник
по инструментам (Гарантирование / Кредитование / Субсидирование).

**Решение.** Все числа в `_REAL_INSTRUMENTS` заменены на 0. То же
сделано с `OKED` в `pages/section.py`. Плашки «Макетные числа»
заменены на «Данные в обработке».

**Файлы:**

- `core/mockup.py` — `_REAL_INSTRUMENTS` все нули;
  докстринг модуля обновлён.
- `core/showcase.py` — плашка «Данные в обработке» (строка 467);
  докстринг модуля обновлён.
- `pages/main.py` — `_mock_badge()` → «Данные в обработке»;
  докстринг модуля и комментарии обновлены.
- `pages/section.py` — `OKED` все нули; три места с плашками
  обновлены (`oked_card()`, `_data_badge()`).
- `tests/test_mockup.py` — `test_проценты_сходятся_со_своими_числами`
  обрабатывает план=0 → процент=0 (был ZeroDivisionError).

**Что считается правильно при нулях:**

- `fact=0, plan=0` → `percent=0` (ветка `if plan > 0 else 0.0` в `card_numbers`)
- `fact=0` / `last_year=0` → `factor=1.0` (дельта показывает «0,0%»)
- `sum_series()` → всё 0
- `for_year()` → работает, месяцы все 0
- `expected_pace()` → зависит только от даты, не от чисел
